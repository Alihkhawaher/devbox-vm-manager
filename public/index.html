The manager is not reachable - retrying every few seconds. Is its console window (or terminal) still open? Start it again with the launcher if it was closed.

Access token needed

This manager only answers pages that carry its access token, so other programs (and the VMs themselves) cannot control it. The easiest fix: open the manager with the link it printed when it started - the console window shows a line like http://127.0.0.1:8777/#token=.... Starting the launcher again also opens it.

Or paste the token here. It is the text inside the file manager-token in the manager's data folder (next to vms.json).

Run a Docker image

Type an image reference and press Run. The image is pulled straight from the registry and runs in its own small, isolated microVM - it starts in seconds, with no Docker, WSL or Hyper-V on this PC. Compose stacks and images that need a full Docker run in a VM with Docker inside it instead (Options > Advanced).
Options - the defaults are usually fine

Ports

No rows: the ports the image declares are published on this PC (the same number when it is free; ports below 1024 move up: 80 becomes 8080, 443 becomes 8443, any other becomes 8000 + the port). Each row is this PC only unless you tick LAN for it. "This PC only" includes the VMs and containers running on this PC.

Port forwards

          
Each forward makes a port inside the VM reachable on this PC at
            127.0.0.1:<host port>. New forwards are this PC only unless you tick
            Reachable from LAN for that row (other devices on your network can then connect; Windows
            Firewall may ask once). Changes on a running VM apply immediately when possible.
